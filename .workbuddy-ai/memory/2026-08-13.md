## Bug fix: "after I login nothing happens, I just remain there"
- Symptom: successful login (vendor/buyer) leaves the user stuck on the login page.
- Root cause: both `VendorLogin`/`BuyerLogin` called `refreshSession()` (a 2nd `/api/auth` `marketplace-session`
  request that re-reads the **cookie**) and only then `navigate()`. If that round-trip returned `null`
  (proxy dropped `Set-Cookie`, SameSite/origin quirk, transient API error), `session` stayed `null` and
  `MarketplaceProtectedRoute` bounced them back to `/vendor-login` (or `/buyer-login`). Silent loop.
- Fix: added `login(session)` to `MarketplaceAuthContext` that sets `session` + syncs localStorage directly
  from the **login response** (no 2nd round-trip). Login pages now call `login({ id, role, email, name })`
  built from `result.vendor` / `result.buyer`, then navigate. Cookie is still set server-side for API auth;
  `refreshSession()` still re-hydrates on full reloads. Navigation no longer depends on the fragile re-fetch.
- Files: `src/context/MarketplaceAuthContext.tsx`, `src/pages/vendor/VendorLogin.tsx`,
  `src/pages/buyer/BuyerLogin.tsx`.
- Not yet runtime-verified (sandbox fork-blocked). User should retest login → dashboard. If the dashboard
  then shows empty/"please sign in", the underlying cookie isn't being set and that's a server/proxy issue
  (check `coconoto_marketplace_session` cookie in devtools). VintageLogin/TweetitLogin NOT touched (legacy
  flow) — ask user if those are the ones affected.
